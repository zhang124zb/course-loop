# CourseLoop 扩展方向与学校迁移

设计基线：2026-10-22。本文描述后续演进与准入条件，不代表这些能力已经实现或排期获批。

## 1. 优先保护已经建立的数据关系

课程、班级、成员、知识点、资源、任务、提交与报告通过稳定标识关联。首期只种入一门 Python 课程，但查询与权限始终使用课程和班级关系；新增课程不应修改全局常量或复制整套页面。

三种“层级”要分开：资源的基础巩固 / 综合开发 / 竞赛备赛，任务的基础 / 进阶 / 项目，以及赛事的周常 / 月度 / 校级。它们可以通过知识点与任务关系对应，不能复用同一字段后假定一一对应。

本期不提前建空业务表冒充已完成扩展。新增领域时以数据库迁移、接口契约和权限测试扩展，保持现有提交和报告可追溯。

## 2. 学习领域的下一步

先补齐题目版本、知识点标签和学生练习证据，再建立掌握度与路径推荐。掌握度必须说明分母、近期性、帮助使用与重复提交等规则；没有练习证据的知识点应显示未知，不能补一个好看的雷达分数。

学生 AI 答疑单独建设权限、调用额度、任务上下文和竞赛时禁用规则；不直接复用教师能够读取的全班数据。提示、诊断和参考答案在不同学习阶段有不同权限。

## 3. 真实竞赛与评价如何接入

赛事引用题目及测试集版本，关联课程和参加范围。三级赛事可以共用流程引擎和题库，但分别规定报名、时间窗、排名与成绩用途。首次开放真实竞赛前，验证同时提交、截止时刻、重试、结果重算及审计。

评价以课堂实训、自主练习、各级竞赛、期末项目四维为独立来源。保存权重版本、证据范围、换算规则和教师发布结果；缺失或待评不能自动算零。同一提交不得在未说明的情况下被重复计入多个维度。

正式成绩只有在学校明确评分制度、等价考核、申诉、更正、批准人与保留周期后才可启用。AI 不作为不可复核的唯一评分依据。相似度和切屏仅为需要人工核查的线索，不自动认定作弊。

## 4. 判题服务的替换边界

本期固定示例运行器只是演示适配器，不能通过增加一项“已审核”字段升级为任意代码运行平台。后续独立判题适配器需要接收提交标识、题目与测试集版本、语言及资源限制，返回状态、分数、用例摘要与运行证据。

独立服务在应用凭证、文件系统和网络上与教学后台隔离；运行默认禁止外联，并验证进程、CPU、内存、磁盘、时间、输出量与清理机制。使用持久任务标识防止重试造成重复计分，判题回调需鉴权且结果可追溯。

在验证隔离环境前，维持“未知代码仅保存待评”，不能以教师确认、代码静态扫描或限时子进程代替沙箱。

## 5. 学校部署必须重新评审的事项

迁移是新的部署阶段，不是把本机监听地址改成公网地址。至少确认实际人数、同时上课与比赛规模、可接受中断和数据损失、维护负责人、学校身份系统及数据处理要求。

建议路线是保留 Django 业务和显式数据关系，将数据库迁移到 PostgreSQL，使用学校批准的文件存储与备份位置；需要隔离判题和 AI 后台任务时再增加独立服务。容量与恢复目标应由实际负载和学校要求确定，本文不承诺未经验证的并发数字。

迁移前须完成 HTTPS、反向代理信任、来源与 Cookie 策略、密钥管理、数据库最小权限、补丁升级、服务监控和恢复演练。统一身份接入后仍保留课程、班级和教师关系鉴权，不能把“已登录学校账号”等同于可访问任意班级。

单校多课程和多校平台不是同一范围。若进入多校部署，再决定是否引入学校实体或租户边界，并验证所有查询、导出、日志、文件和 AI 上下文均按学校隔离；本期不宣称具备多租户能力。

## 6. AI 演进与数据外发

保留同一业务调用边界下的本地 Ollama 与受控外部兼容服务。更换服务前验证模型、超时、返回结构、输入容量和教学建议质量；协议兼容不等于能力、隐私和输出质量相同。

学校数据接入外部模型需要学校明确批准接收方、字段、保存期限和日志规则。首期仅使用示例数据的许可不能延伸为允许上传真实学生代码或身份信息。外部服务故障不得触发未批准的自动外发或降级。

## 7. 数据迁移、备份和回退

先在副本执行迁移并核对记录数、外键归属、权限、提交状态和报告证据，再安排写入暂停窗口。迁移前后均保存可恢复备份，不将数据库和密钥直接提交到 Git。

恢复目标不仅是数据库可以打开，还包括用户可登录、任务可访问、提交状态正确、报告可追溯。AI 密钥应从受保护的密钥材料恢复或重新配置；跨机器直接复制加密字段不一定可解密。

若迁移失败，按预先规定回到旧版本和相配数据库；避免新旧系统同时写入造成分叉。发布包、数据库迁移和配置变更要能对应到同一版本。部署与回退结果由实际演练验证，不用本机演示记录代替。
