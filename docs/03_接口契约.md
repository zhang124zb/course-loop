# CourseLoop 接口契约

设计基线：2026-10-22。路径与 `server/teaching/urls.py` 对齐；模型见[数据模型](02_数据模型.md)。本稿规定接口边界与验收要求，实际连通和越权检查须另行验证。

首期是同源 Django 网页应用：写操作通过带 CSRF 的 HTML 表单提交，`/api/v1/` 仅提供只读 JSON 及扩展状态。不把网页表单接口包装成已经稳定的完整 REST 平台。

## 1. 通用规则

- 根地址为本机服务的 `http://127.0.0.1:<运行端口>/`；端口以实际启动说明为准，不开放跨域写入。
- 身份来自服务端会话 Cookie。浏览器提交表单必须携带 CSRF；后端不接受请求内自报角色、学生身份、可信分数或执行资格。
- 网页 GET 读取页面；POST 执行操作。成功写入通常重定向到结果页，避免刷新重复提交。只读 GET 不用于发布、采纳、测试 AI 或更改配置。
- 未登录访问网页进入登录流程；只读 JSON 接口返回 `401`。对象越权通过权限过滤返回 `404` 或角色检查返回 `403`，不得泄露不属于当前用户的内容。
- 表单数据错误返回带字段错误的 HTML 和 `400`；CSRF 失败为 `403`。首期错误格式按页面与 JSON 区分，客户端不能假定所有响应都是 JSON。
- 时间在页面按 Asia/Shanghai 展示；接口若输出时间，采用带时区的 ISO 8601 字符串。无结果用空值，不以零分代替待评。
- 不接受跨对象关系篡改：班级、题目版本、资源须属同一课程，学生提交须属于可见且允许提交的教学任务。
- 不支持的方法应返回 `405`；竞赛和评价占位返回 `501`，不能返回假数据声称完成。

JSON 未登录错误形状：

```json
{"error":{"code":"authentication_required","message":"请先登录。"}}
```

错误的展示文案可调整，调用方应判断状态码和 `code`。服务端错误不能包含密钥、密码、会话、内部路径或堆栈。

## 2. 身份与管理页面

`GET /login/` 显示登录页，`POST /login/` 接收账号和密码；失败不区分账号不存在与密码错误，并执行登录节流。登录后的返回地址必须是允许的本机同源路径。

`POST /logout/` 退出并使当前会话失效。`GET /` 与 `GET /dashboard/` 显示当前账号有权限的工作台。

下列管理入口仅管理员可操作：

- `GET/POST /manage/accounts/`：创建账号时 `action=create`，字段为 `username`、`display_name`、`role`、`password1`、`password2`；另有 `activate`、`deactivate`、`reset_password` 操作，使用 `user_id` 定位目标。密码不回显、不写审计详情。账号 3—40 位，使用字母、数字、点、下划线或短横线，并检查重复。
- `GET/POST /manage/classes/`：`action=create_course` 创建课程，字段为 `slug`、`title`、`description`、`language`；`action=create_class` 创建班级，字段为 `course`、`teacher`、`name`、`students`；`action=enroll` 按 `classroom`、`students` 替换完整学生名单。替换名单须明确影响，历史提交不能被顺带删除。
- `GET/POST /manage/ai/`：查看脱敏配置或保存新配置；字段见第 5 节。
- `POST /manage/ai/test/`：显式测试当前配置的真实模型调用；它不是只读操作，不能使用 GET 或学生权限触发。
- `GET /manage/audit/`：查看授权范围内的事件；不提供公开审计或凭证导出接口。

管理页面可能以不同表单区分操作，调用方必须使用服务端实际渲染字段，不能依赖未定义的 JSON 写入协议。

## 3. 资源与教学任务

### 资源

- `GET /resources/`：当前课程范围资源列表，学生只读取已发布资源。
- `GET/POST /resources/new/`：教师或管理员创建资源。
- `GET /resources/<id>/`：授权资源详情。
- `GET/POST /resources/<id>/edit/`：管理员或符合创建者及课程权限要求的教师编辑。
- `GET /resources/<id>/download/`：通过身份与课程权限后下载附件；磁盘路径不能作为下载参数。
- `POST /resources/<id>/complete/`：学生为自己记录完成，不接受另一个学生标识。

资源表单字段为 `course`、`title`、`level`、`kind`、`body`、`url`、`file`、`is_published`。正文、链接、附件至少提供一种。附件用 `multipart/form-data`；其余表单按页面编码。

当前附件契约为 1 字节至 20 MiB，支持 PDF、PPTX、MP4、WEBM、TXT、MD，并检查类型特征或文本编码，不只依赖扩展名。TXT/MD 使用 UTF-8。通过检查不等于文件已被恶意内容扫描；下载仍需权限，原文件名不能成为存储路径。外部资源链接仅支持无账号密码的 HTTPS，后端不代为抓取。

### 题目与任务发布

- `GET /teaching/`：教师或管理员的教学组织视图。
- `GET/POST /tasks/new/`：创建题目及初始版本。
- `GET/POST /tasks/<id>/version/`：为现有题目创建新版本，不覆盖旧版本。
- `GET/POST /assignments/new/`：创建教学任务。
- `GET /assignments/<id>/`：授权任务详情；学生不可见草稿。
- `GET/POST /assignments/<id>/edit/`：授权教师或管理员编辑与发布。

题目创建字段为 `course`、`title`、`level`、`knowledge_points_text`、`prompt`、`starter_code`。知识点文本最多 500 字符、题目说明最多 30,000 字符、初始代码最多 20,000 字符。创建新题目不允许自行注册可执行代码。

任务字段为 `classroom`、`task_version`、`title`、`stage`、`status`、`due_at`、`resources`。阶段为 `before/during/after`，状态为 `draft/published/closed`。已创建任务的班级与题目版本不能通过普通编辑换绑；关联资源必须同课程，发布时不得带未发布资料。

## 4. 提交与结果

`POST /assignments/<id>/submit/` 仅供任务所属班级的学生提交。表单字段为：

- `source`：保留空白的 Python 源码，最多 20,000 字符。
- `request_id`：UUID，用于同一学生的请求去重。

任务必须处于允许提交的发布状态且符合截止规则。`student` 由会话确定，`source_hash`、`fixture_id`、分数和结果由服务端确定；客户端声明无效。

服务端只匹配当前题目版本关联的仓库固定示例。完全匹配并通过仓库内容校验时，运行固定代码并保存 `completed` 或 `error`。任意编辑内容保存为 `pending`，分数为空，页面清楚说明未执行。提交接口不是任意 Python 执行服务。

同一学生在同一任务重复使用相同 `request_id` 时，重定向到已有提交，不重评或改写它；若标识已用于其他任务则拒绝。实际重复和并发行为应在验证中核对。源代码是否相同与请求是否重复是两件事，不能仅用代码哈希删除正常练习历史。

`GET /submissions/<id>/` 显示授权提交、状态、示例结果及用例摘要。学生只看自己的；教师只看本人任课班级；管理员按管理权限读取。`pending` 不显示伪造结果，`error` 不当作学生零分。

## 5. 教学诊断与 AI 配置

`POST /assignments/<id>/diagnose/` 由授权教师或管理员触发，使用该任务每名学生最新提交生成证据，再调用配置的模型。证据区分已评、待评、评测错误和未提交；没有学生提交时不生成虚构诊断。

`GET /reports/<id>/` 查看授权报告。报告保留状态、证据快照、生成时间、模型名和配置版本；生成失败展示错误而不是成功内容。

`POST /reports/<id>/adopt/` 由授权教师或管理员手动采纳已成功生成的报告，记录时间及审计事件。不得由模型、学生或跨班教师触发；重复操作应避免重复业务副作用。采纳本身不发布新任务、不修改提交或正式成绩。

AI 管理表单字段为 `label`、`base_url`、`model`、`timeout_seconds`、`api_key`、`clear_key`。超时约束为 5—120 秒。`api_key` 留空保留已有密钥；选择清除与填写新密钥互斥；密码型输入不回显。配置返回只允许 `key_configured` 等脱敏状态，不返回原密钥或加密材料。

本机地址归一为 `http://127.0.0.1:11434/v1`。外部仅限操作者在运行配置中明确允许的 HTTPS 域、443 端口和批准路径，不跟随重定向，不允许任意内网目标。保存配置与连接测试均使用同样的校验规则；超时、并发和响应体有上限，不静默换用别的服务。

## 6. 只读 JSON 接口

以下接口使用与网页相同的会话与对象权限，只接受 GET，不另建绕过权限的数据通道：

- `GET /api/v1/courses/`：返回 `items` 数组，各项为 `id`、`slug`、`title`、`language`。仅包含当前账号可访问课程，不能枚举无关班级。
- `GET /api/v1/assignments/<id>/`：返回 `id`、`title`、`stage`、`status`、`course_id`、`classroom_id`、`task_version_id`、`task_version`、`prompt`、`due_at`。其中 `task_version` 是版本号，`task_version_id` 是版本实体标识。学生不能借 API 读取草稿或参考结果。
- `GET /api/v1/submissions/<id>/`：返回 `id`、`assignment_id`、`student_id`、`status`、`score`、`passed`、`total`、`source_hash`、`result`、`created_at`。本接口不返回源代码正文；网页详情另行鉴权。学生只能访问自己的提交。
- `GET /api/v1/extension-points/`：返回 `version`、`implemented`、`planned`、`code_execution`、`official_grades`。本期 `version` 为 `v1`，`code_execution` 为 `reviewed_repository_examples_only`，`official_grades` 为 `false`；`planned` 描述赛评路径及未实现状态。`implemented` 是服务代码的能力声明，不等于相关验收已经通过；教师诊断仍通过网页 POST 触发，并未因此新增 JSON 写接口。

以上字段已按当前 `views.py` 核对定义，仍需实际请求验证。接口不返回密码、API 密钥、解密材料或原始数据库路径，不以首期文档承诺对第三方长期兼容。

待评提交的结果语义如下，标识和哈希为展示示例：

```json
{
  "id": 12,
  "assignment_id": 3,
  "student_id": 4,
  "status": "pending",
  "score": null,
  "passed": 0,
  "total": 0,
  "source_hash": "<服务端计算的SHA-256>",
  "result": {
    "status": "pending",
    "score": null,
    "passed": 0,
    "total": 0,
    "fixture_id": "",
    "cases": [],
    "message": "已保存为待评测；当前代码未执行。"
  },
  "created_at": "2026-10-22T08:00:00+00:00"
}
```

`passed=0,total=0` 表示没有用例执行，不能展示为“0%通过”或“成绩0分”。说明文本可以变化；状态、空分数和执行类型才是判断依据。

## 7. 扩展占位与后续版本

`GET /api/v1/contests/` 与 `GET /api/v1/evaluations/` 明确返回未实现状态：

```json
{"error":{"code":"not_implemented","message":"该业务尚未接入真实服务。"},"status":"planned"}
```

状态码为 `501`；文案可调整。前端可据此展示原型入口或建设说明，不能把占位接口当作赛事或正式成绩来源。

后续新增写入 API 前，单独规定版本、认证、幂等、分页、错误结构和审计，不将现有网页路径未经评审直接当作对外协议。判题回调与模型工具执行均不属于本期开放接口。
