# CourseLoop · 课赛融合平台交互原型

> **这是交互原型，不是正式教学系统。** 所有班级、学生、成绩、赛程和反馈均为示例数据。AI 建议与代码评测为预设流程演示，没有接入真实模型或代码执行沙箱。

CourseLoop 探索“教学 → 自主实训 → 三级竞赛 → 过程评价 → 教学改进”的完整链路，支持学生、教师、管理员三个演示视角。

## 可以体验什么

- **教**：课前预习、课中实操、课后训练，以及教师审核教学诊断建议。
- **学**：三层资源、基础/进阶/项目任务、预设代码纠错与新题复测。
- **赛**：单元闯关、月度挑战、校级选拔与等价考核，组赛草案和教师发布。
- **评**：四维权重、过程试算、证据说明、项目量规、报告导出和评价异议。
- **闭环**：发现问题 → 教师确认 → 针对补练 → 新题复测 → 教师验证。

## 推荐体验顺序

1. 学生视角进入“分层实训 → 列表平均值与空输入”，运行边界遗漏示例。
2. 查看递进提示，切换到订正示例并提交，再查看过程评价的变化。
3. 切换教师视角，查看诊断报告并确认安排训练与复测。
4. 学生完成 T101 和 T203；教师核对证据后确认改善，关闭干预。
5. 教师调整四维权重、创建赛事草案，或按量规评价项目。
6. 管理员可以新增资源、导出体验数据或恢复初始样例。

## 本地运行

需要 Node.js。应用没有第三方运行依赖：

```sh
npm start
```

打开 `http://127.0.0.1:4173`。也可以直接打开 `dist/index.html`。

```sh
npm run check
```

## GitHub Pages

仓库使用 `.github/workflows/pages.yml` 将 `dist/` 发布到 GitHub Pages。推送 `main` 后自动检查脚本语法并部署。

GitHub Pages 的发布来源设置为 **GitHub Actions**。项目站点使用 `/course-loop/` 子路径，静态文件采用相对引用，页面采用哈希路由。

## 数据与实现边界

- 数据仅保存在当前浏览器，不会跨设备同步。
- 角色切换是演示功能，不是真实登录或服务端权限。
- 代码评测只匹配预设示例，不执行任意代码。
- AI 助教、诊断与组赛建议是演示模板，不调用真实模型。
- 项目文件只记录文件名，不读取或上传文件内容。
- 四维分数为过程试算，不形成正式教务成绩。

请勿输入真实学生个人信息或把本原型用于正式考试。后续建设需补齐身份、服务端数据、隔离判题、模型验证和正式评价制度。

## 文件结构

```text
dist/                      静态网页、样式、交互与示例数据
.github/workflows/pages.yml GitHub Pages 自动部署
serve.mjs                  本机预览服务
package.json               运行与语法检查命令
验证记录.md                 原型浏览器检查记录
```

本项目曾完成 18 项浏览器交互检查；详见[验证记录](验证记录.md)。这些检查不等同于生产安全审计、性能压测或教学效果验证。
