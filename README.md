# CourseLoop · 在线教学演示与本机教学版

本项目包含两个运行入口：**本机教学版**具有真实登录、数据库、资源与任务管理、固定示例运行及 DeepSeek / Ollama 教师诊断；**GitHub Pages 在线教学演示**复用本机版界面，以全新模拟数据展示教学流程。早期四域交互原型保留为次级入口。

## 本机教学版

面向大学 Python 程序设计课程，使用明确标注的模拟班级与学生。默认只绑定 `127.0.0.1:8080`，适用于一个人使用不同账号演示，不开放局域网和公网。

1. 在 Windows 上安装 Python（本次验证版本 3.14.6）。
2. 双击 `启动本机教学.cmd`。首次启动需联网安装锁定依赖，之后正常运行无需重复安装。
3. 查看运行目录中的 `demo-accounts.txt` 获取独立生成的管理员、教师和学生账号（默认目录为 `.runtime`，可按指南迁移）；切换角色前先退出。
4. 打开 `http://127.0.0.1:8080/`。

2026-10-22 已实测本机后端调用 DeepSeek 官方 API：地址 `https://api.deepseek.com/v1`，模型名 `deepseek-flash`，按[官方文档](https://api-docs.deepseek.com/)当前由 V4.1-Flash-1017 提供服务。连接测试与按模拟班级提交生成报告均已通过，模型别名后续可能更新。密钥由管理员在本机配置，仓库不提供共享密钥或公开 AI 后台。

也可使用本机 Ollama 已安装模型，种子配置为 `qwen3.5:4b`；启动脚本在服务未运行时尝试后台启动，不自动下载模型。切换到 Ollama 时应明确清除云服务密钥。

- 学生：访问已发布课程资源，记录学习完成，提交代码并查看自己的反馈。
- 教师：维护分层资源与不可变题目版本，安排课前、课中、课后任务，查看班级提交与学习记录，生成并确认 AI 教学建议。
- 管理员：创建与停用账号、重置密码，维护课程与班级名单，配置和测试模型，查看操作日志。
- 代码评测：只真实运行服务器固定、哈希校验通过的六份已审核示例；学生编辑代码只保存为待评测，不作为错误或零分。教师新增题目不自动获得执行权限。
- AI：按当前班级名单及每名学生最新提交生成报告，保留证据快照；不自动发布任务、执行代码或改分。学生聊天答疑留待后续扩展。

技术栈：Django 5.2.18 LTS、SQLite、Waitress、服务器端模板；密钥使用 Fernet 加密保存。依赖版本见 `requirements.lock`。学校多人部署前需迁移与验收，不能直接把本机演示版开放出去。

运行数据、账号文件、上传附件和本机密钥位于独立运行目录。真实服务密钥启用前须将数据迁至非同步私有目录，并通过已忽略的 `.local-settings.json` 指定目录和允许的外部主机；文件只存目录与域名，不存密钥。启动、管理命令和备份使用相同配置；详见启动指南。默认 `.runtime/` 仍已排除出 Git。

## GitHub Pages 在线教学演示

> **这是静态在线演示，暂未接入真实后台。** 选择学生、教师、管理员视角，无需真实账号或密码。资源、任务、提交和管理操作只保存在当前浏览器；代码反馈与教学建议为明确标注的模拟结果，不调用模型或执行代码。

在线版复用本机教学版的界面与样式：学生学习资源、记录完成、提交代码与查看反馈；教师管理资源、题目和课前/课中/课后任务，查看当前班级最新提交的证据并确认演示报告；管理员维护模拟账号、课程和班级。可刷新保留数据，也可重置本浏览器的演示数据。模型密钥输入已停用，真实密钥只在自己的本机服务中配置。

在线内容由全新公开模拟数据构建，不导出本机数据库、账号密码、会话、CSRF 或密钥。不同设备与浏览器之间不共享这些操作，视角选择不构成真实身份认证。浏览器不能保存时会明确提示临时状态。

建议先用学生视角完成一项资源并提交练习，再切换教师查看提交、生成并采纳演示建议，最后用管理员维护模拟账号和班级。课赛融合的完整构想保留在下方早期原型中。

## 早期课赛融合原型（次级入口）

以下四域构想在 `dist/prototype/` 保留，使用独立的浏览器演示存储；教学主入口已经替换为本机版同款界面。

- **教**：课前预习、课中实操、课后训练，以及教师审核教学诊断建议。
- **学**：三层资源、基础/进阶/项目任务、预设代码纠错与新题复测。
- **赛**：单元闯关、月度挑战、校级选拔与等价考核，组赛草案和教师发布。
- **评**：四维权重、过程试算、证据说明、项目量规、报告导出和评价异议。
- **闭环**：发现问题 → 教师确认 → 针对补练 → 新题复测 → 教师验证。

## 早期原型体验顺序

1. 学生视角进入“分层实训 → 列表平均值与空输入”，运行边界遗漏示例。
2. 查看递进提示，切换到订正示例并提交，再查看过程评价的变化。
3. 切换教师视角，查看诊断报告并确认安排训练与复测。
4. 学生完成 T101 和 T203；教师核对证据后确认改善，关闭干预。
5. 教师调整四维权重、创建赛事草案，或按量规评价项目。
6. 管理员可以新增资源、导出体验数据或恢复初始样例。

## 本地运行

需要 Node.js。应用没有第三方运行依赖：

```sh
npm start
```

打开 `http://127.0.0.1:4173`。也可以直接打开 `dist/index.html`。

```sh
npm run check
```

## GitHub Pages

仓库使用 `.github/workflows/pages.yml` 将 `dist/` 发布到 GitHub Pages。推送 `main` 后自动检查脚本语法并部署。`npm run check` 还会检查各教学演示脚本并运行静态状态流程测试；本次新增的11项真实浏览器流程覆盖角色操作、刷新保存、文本转义、手机布局和存储失败提示。

GitHub Pages 的发布来源设置为 **GitHub Actions**。项目站点使用 `/course-loop/` 子路径，静态文件采用相对引用，页面采用哈希路由。

## 线上静态原型的数据与实现边界

- 数据仅保存在当前浏览器，不会跨设备同步。
- 角色切换是演示功能，不是真实登录或服务端权限。
- 代码评测只匹配预设示例，不执行任意代码。
- AI 助教、诊断与组赛建议是演示模板，不调用真实模型。
- 项目文件只记录文件名，不读取或上传文件内容。
- 四维分数为过程试算，不形成正式教务成绩。

请勿输入真实学生个人信息或把本原型用于正式考试。后续建设需补齐身份、服务端数据、隔离判题、模型验证和正式评价制度。
